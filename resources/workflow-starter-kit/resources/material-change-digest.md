# Material Change Digest

Published by Nymrel. Use this template to explain a project update without
copying full agent transcripts or creating another task system. It works in a
message, issue, pull request, or project note.

> **Project / goal — what changed.**  
> Responsible role: [source-reported role, or unverified].  
> Next: [one concrete action].  
> Checkpoint: [stated time, or not supplied].  
> Evidence: [original source and relevant revision].  
> Still unverified: [material limitation].

Report a change when it affects the outcome, accepted responsibility, source
revision, blocker, next action, or checkpoint. A later retrieval time alone is
not progress. A named role in a note is not proof that someone accepted the work
or is currently executing it.

Keep source event time, observation time, and a planned future checkpoint
distinct. If the source supplies no checkpoint, write "not supplied." Do not
derive a due time from the existence of a recurring schedule.

Separate what the source reports from what has been verified. A posted handoff
does not prove acknowledgment. A reported completion does not prove accepted
completion, successful tests, deployment, public availability, or real use.
Link the original source so the reader can assess the evidence and its scope.

When a later update explicitly corrects or replaces an earlier one, retain both
sources and explain the correction narrowly. Do not let the newest timestamp
silently override conflicting evidence. Historical next actions should be
clearly marked as history rather than active instructions.

Use only the information needed for the audience. Verify that each source link
and quoted detail can be shared before making a digest public. Do not copy
private conversations, credentials, customer records, or internal handoff text
into a public update. Publishing remains a separate action under the user's
actual authorization.

## Synthetic example

> **Release-summary experiment — the local fixture now detects unsupported claims.**  
> Responsible role: project maintainer, reported in the review note; acceptance unverified.  
> Next: run the agreed baseline comparison.  
> Checkpoint: not supplied.  
> Evidence: local synthetic test report, fixture revision 2.  
> Still unverified: comparison outcome, actual-host behavior, and adoption.

This is an illustrative update, not a report of an executed experiment.
